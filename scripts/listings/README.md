# Duck Epics — listing content (master) & updater

Single source of truth for the Trello Power-Up **catalog listing** (name, overview,
description) across **all 24 Trello locales**, plus a one-shot updater that pushes every
language to Trello via the REST API. Keeps the store listing version-controlled and lets us
change the copy **for all languages at once**.

- **Power-Up id:** `6a6dbb0953912e0f415de989`
- **Listing name (all locales):** `Duck Epics — Sub-tasks & Progress`
- **Default / fallback locale:** `en-US` (must stay the FIRST listing — Trello serves the first
  listing to any viewer whose locale doesn't match).
- **GIFs used in every description** (hosted on our Cloudflare Pages):
  - `…/assets/gifs/duck-epics-make-subscription.gif`
  - `…/assets/gifs/duck-epics-create-subtask.gif`
  - `…/assets/gifs/duck-epics-status-done.gif`

## Files
- **`content.js`** — the master content: `{ NAME, GIF_BASE, LISTINGS: { <locale>: { overview, description } } }`.
  Descriptions are Markdown (`##`/`###` headings, bullets, embedded `![](gif)` images, a
  "100% free" line, and a `Developed by [Duck.design](https://duck.design/)` footer).
- **`update-listings.js`** — the browser-console updater. Paste into DevTools on any open
  `trello.com` page (logged in as a listing admin). It reads `content.js`'s data (inline copy),
  then **creates or updates** every locale's listing via the API.

## How to update the listing (all languages at once)
1. Edit the copy in **`content.js`** (change English + the translations you want).
2. Open `https://trello.com` in the browser you're logged into as the Power-Up admin.
3. Open DevTools → Console, paste the contents of **`update-listings.js`**, run.
4. It prints a `{locale: status}` map — all should be `200`.
5. Verify: search the Power-Up catalog for "epic" → Duck Epics.

## Trello listings API (how the updater works)
- **Read:** `GET /1/plugins/{id}?listings=true` → `plugin.listings[]` (`{id, locale, name, overview, description}`).
  The dedicated `/1/plugins/{id}/listings` collection GET returns **404** — use `?listings=true`.
- **Update one:** `PUT /1/plugins/{id}/listings/{listingId}` — form body `name`, `locale`, `overview`,
  `description`, `dsc`.
- **Create one:** `POST /1/plugins/{id}/listings` — same form body.
- **CSRF:** every write needs `dsc=<value of the `dsc` cookie>` (read from `document.cookie`).
- The admin's own "Save" button in the WYSIWYG is unreliable in automation; this API path is the
  reliable one.

`en-US`, `en-GB`, `en-AU`, `ru` are human-reviewed. The other 20 are machine translations
(generated by the assistant) — **have a native speaker review them before any marketing push**,
especially `ja`, `zh-Hans`, `zh-Hant`, `th`, `vi`, `cs`, `hu`, `fi`, `nb`.
