# План разработки — Фаза 1 (MVP)

Каждый шаг = рабочий кусок функциональности + проверка. Тестирование двухуровневое:

- **Мок-стенд** (`test/harness.html`): подменяем Trello-клиент `t` фейковыми досками/карточками/списками. Проверяем логику и вёрстку попапов/секций прямо в браузере, без Trello.
- **Живой тест** на доске `Duck.design Mission Control` через Chrome: деплой на GitHub Pages → включённый Power-Up → реальные клики и скриншоты.

Git: коммит после каждого шага, push по твоей команде.

| Шаг | Что делаю | Как тестирую |
|---|---|---|
| **S0. Каркас + деплой** | Чистим черновик, structure, connector «hello-world», деплой на GitHub Pages | Pages-URL открывается; Power-Up виден и включается на доске |
| **S1. Слой данных** | `epic.js`: чтение/запись pluginData, модель `childRefs`, обёртка REST-клиента | Мок-стенд: связи пишутся/читаются, счётчик корректен |
| **S2. Make Subscription + иконка** | Кнопка пометки родителя, авто-эмодзи (уникальный) + пикер | На карточке: флаг ставится/снимается, иконка присвоена |
| **S3. Привязка родителя / существующей карточки** | «Set/Change parent», «Detach», линк существующей карточки | Связь сохраняется, смена/отвязка работают, циклы блокируются |
| **S4. Форма создания Sub-task** | Попап: имя / доска (дефолт текущая) / колонка (дефолт как у родителя) → создаёт и линкует | Карточка создаётся в нужной колонке и сразу привязана |
| **S5. REST-авторизация** | «Authorize» через `t.getRestApi()` — доступ к архивным | Токен получен; архивные карточки читаются |
| **S6. Бейджи** | Закрытая карточка (`X/Y done` + значок), открытая (прогресс) | Счётчик = число детей в `Completed Tasks`, вкл. архивные |
| **S7. Секция родителя** | Список детей: название, колонка-статус, исполнитель, переход; архивные помечены | Список совпадает с доской, переход работает |
| **S8. Секция ребёнка** | Карточка родителя (иконка+имя) + переход; бейдж на закрытой | На Sub-task виден родитель, клик открывает его |
| **S9. Состояния и мелочи** | Пустые/загрузочные/ошибочные состояния, RU/EN, чистка «битых» связей | Проверка граничных случаев на мок-стенде и доске |
| **S10. Регрессия** | Полный прогон сценария на реальной доске | Создать Subscription → 3 Sub-task в разных колонках → довести одну до Completed → проверить `1/3 done`, архивировать одну → проверить учёт |

## Порядок запуска (chicken-and-egg с API-ключом)

1. Я собираю S0 и деплою на GitHub Pages (нужен push + включённые Pages).
2. Ты создаёшь Power-Up в Trello, указываешь URL коннектора = Pages-URL, генерируешь **API Key**, присылаешь мне.
3. Я вставляю ключ в код, редеплою.
4. Ты включаешь Power-Up на доске.
5. Я тестирую на доске через твой Chrome и иду по S1…S10.

## Definition of Done (Фаза 1)

Родитель показывает верный `X/Y done` (учитывая архивные), список детей с колонками-статусами и переходом; ребёнок показывает родителя; Sub-task создаётся формой; всё в пределах доски `Duck.design Mission Control`; связи хранятся без сканирования доски.
